## AI動画生成ツールをUdemyに公開する時の3つの審査落とし穴

我々はJQCA（日本量子コンピューティング協会）で、量子計算やAI×量子のUdemy講座を自動生成・公開しています。

edge-tts（音声読み上げ）→ Playwright（Webページ→画像キャプチャ）→ ffmpeg（動画結合）という、ほぼ完全自動のパイプラインを作り、5時間の講座を2時間で生成できるようになりました。

しかし、最初のUdemy公開で「審査落ち」を3度繰り返しました。その過程で見つけた落とし穴と対策をシェアします。

### 落とし穴1: コース画像に文字・数字を絶対に入れてはいけない

Udemyの審査ガイドラインには「コース画像にテキストを含めない」という厳格なルールがあります。

我々は最初、スライド画像をそのまま背景にしていました。その画像には：
- コース名（「量子エンジニア（アニーリング）エントリー講座」等）
- 「全5回」などの数字
- 「一般社団法人…」というテキスト

が含まれていました。

**落ちた理由**: タイトルや説明文は別フィールドで入力する。コース画像は「ビジュアルのみ」が前提。

**対策**: 元の背景画像（文字なし・スピン格子やエネルギー地形のイラスト）を用意し、テキストは絶対に重ねない。代わりに、画像そのもので視覚的に「内容」を表現します。例えば、量子アニーリングならエネルギー地形の山谷、量子ゲートなら量子回路のシンボルを配置します。

ルール詳細: https://support.udemy.com/hc/ja/articles/229232347

### 落とし穴2: AI利用の開示を必ず含める

2024年のUdemyポリシー更新で、AI（特に音声合成や画像生成）を使用したコースは、コース説明欄に「本コースにはAIの使用が含まれています。」と必ず記述する必要が出ました。

我々は最初この開示をしませんでした。

**落ちた理由**: AI使用の透明性不足。Udemyは「生成型AIとの区別」をCreator責任で明示すること。

**対策**: コース説明文の冒頭に、以下の文を一字一句変えずに追記：
```
本コースにはAIの使用が含まれています。
```

さらに「どのタイミングでAIを使っているか」も詳しく書くと◎。例：
```
本コースにはAIの使用が含まれています。講座の音声は edge-tts（Text-to-Speech）で自動生成されています。
```

ルール詳細: https://support.udemy.com/hc/ja/articles/33490280024087

### 落とし穴3: 音質バラツキとサンプルレート不一致

edge-tts の音声は十分なクオリティですが、セグメント結合やエンコードプロセスで音量がばらつくことがあります。Udemyで再生すると「声が小さい→大きい→小さい」と不快になります。

さらに、ffmpeg concat demuxer で複数の mp4 を結合する際、音声サンプルレートが不一致だと duration が壊れることがあります。

**対策**:
```bash
# 全ストリームを48kHzに統一
ffmpeg -i segment1.mp4 -acodec aac -ar 48000 -c:v copy seg1_48k.mp4
ffmpeg -i segment2.mp4 -acodec aac -ar 48000 -c:v copy seg2_48k.mp4

# loudnorm で音量正規化
ffmpeg -i input.mp3 -af "loudnorm=I=-16:TP=-1.5:LRA=11" output.mp3

# concat demuxer で結合（-c copy は短時間で完了）
ffmpeg -f concat -safe 0 -i filelist.txt -c copy output.mp4
```

## まとめ

AI動画生成は「作ること」は簡単になりましたが、プラットフォーム審査は人間の目が入ります。

1. **ビジュアルはビジュアル、テキストはテキスト** — 別フィールドで管理
2. **AI利用は透明に開示** — 隠さない、むしろ正確に使っていることをアピール
3. **音声・映像は品質チェック** — エンコード時点で正規化とサンプルレート統一が必須

この3点を潰したことで、我々は再提出で審査を通過できました。
